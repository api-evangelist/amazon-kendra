<p>There is consistent customer feedback that AI assistants are the most useful when users can interface with them within the productivity tools they already use on a daily basis, to avoid switching applications and context. Web applications like <a href="https://aws.amazon.com/q/business/" rel="noopener" target="_blank">Amazon Q Business</a> and <a href="https://slack.com/" rel="noopener" target="_blank">Slack</a> have become essential environments for modern AI assistant deployment. This post explores how diverse interfaces enhance user interaction, improve accessibility, and cater to varying preferences.</p> 
<p>By offering seamless experiences across environments, organizations can increase user satisfaction and adoption rates. The assistant employs <a href="https://aws.amazon.com/what-is/retrieval-augmented-generation/" rel="noopener" target="_blank">Retrieval Augmented Generation (RAG)</a>, a technique that integrates credible and authoritative sources within responses across these interfaces, bolstering trustworthiness and educational value. This multi-interface, RAG-powered approach not only strives to meet the flexibility demands of modern users, but also fosters a more informed and engaged user base, ultimately maximizing the assistant’s effectiveness and reach. By combining RAG with multiple interfaces, the assistant delivers consistent, accurate, and contextually relevant information regardless of the user’s preferred environment and productivity tools.</p>

<h2>Solution components</h2> 
<p>In this section, we discuss two key components to the solution: the data sources and vector database.</p> 
<h3>Data sources</h3> 
<p>We use <a href="https://github.com/spack/spack/tree/develop/lib/spack/docs" rel="noopener" target="_blank">Spack documentation</a> RST (ReStructured Text) files uploaded in an <a href="http://aws.amazon.com/s3" rel="noopener" target="_blank">Amazon Simple Storage Service</a> (Amazon S3) bucket. Whenever the assistant returns it as a source, it will be a link in the specific portion of the Spack documentation and not <a href="https://spack.readthedocs.io/en/latest/containers.html" rel="noopener" target="_blank">the top of a source page</a>. For example, <a href="https://spack.readthedocs.io/en/latest/containers.html#spack-images-on-docker-hub" rel="noopener" target="_blank">Spack images on Docker Hub</a>.</p> 
<p><a href="https://spack.io/" rel="noopener" target="_blank">Spack</a> is a versatile package manager for supercomputers, Linux, and macOS that revolutionizes scientific software installation by allowing multiple versions, configurations, environments, and compilers to coexist on a single machine. Developed by Todd Gamblin at the <a href="https://www.llnl.gov/" rel="noopener" target="_blank">Lawrence Livermore National Laboratory</a> in 2013, Spack addresses the limitations of traditional package managers in high-performance computing (HPC) environments. Brian Weston, Cloud Transformation for Mission Science Program Lead at LLNL, advised in the development of this assistant.</p> 
<p>Additionally, we use text files uploaded to an S3 bucket that is accessible through an <a href="https://aws.amazon.com/cloudfront/" rel="noopener" target="_blank">Amazon CloudFront</a> link. There is also an automated ingestion job from Slack conversation data to the S3 bucket powered by an <a href="https://aws.amazon.com/pm/lambda/?gclid=EAIaIQobChMIzZTBtdXViQMV6mBHAR1hhgAzEAAYASAAEgLWN_D_BwE&amp;trk=73f686c8-9606-40ad-852f-7b2bcafa68fe&amp;sc_channel=ps&amp;ef_id=EAIaIQobChMIzZTBtdXViQMV6mBHAR1hhgAzEAAYASAAEgLWN_D_BwE:G:s&amp;s_kwcid=AL!4422!3!651212652666!e!!g!!lambda!909122559!45462427876" rel="noopener" target="_blank">AWS Lambda</a> function. This enables the assistant to also use previous conversations from users to answer questions and cite its sources. We opted to use CloudFront links as opposed to using Slack links because when this source is cited in Amazon Q, the user might not have access to the Slack data. There is also an alternative to this methodology using the <a href="https://docs.aws.amazon.com/kendra/latest/dg/data-source-slack.html" rel="noopener" target="_blank">Slack connector</a> for <a href="https://aws.amazon.com/kendra/" rel="noopener" target="_blank">Amazon Kendra</a>.</p> 
<p>This solution could support other data types such as PDFs, Word documents, and more as long as their text can be extracted and fed into the vector database with some code changes. Their raw files can be served in a CloudFront distribution.</p>

The solution also includes automatic daily ingestion of data from Slack into the application using <a href="https://aws.amazon.com/eventbridge/" rel="noopener" target="_blank">Amazon EventBridge</a>.</p> 
<h3>Vector database</h3> 
<p>This solution uses Amazon Kendra as its <a href="https://aws.amazon.com/what-is/vector-databases/" rel="noopener" target="_blank">vector database</a>, offering significant advantages in simplicity and cost-effectiveness. As a fully managed AWS service, Amazon Kendra reduces both development and maintenance costs. Amazon Q, which supports two types of retrievers (native retriever and Amazon Kendra), is seamlessly integrated into this setup. By using Amazon Kendra, the solution efficiently employs the same retriever for both the Amazon Q and Slack interfaces. This approach not only streamlines the overall architecture but also provides a more consistent user experience across both environments. The result is a cohesive, cost-efficient system that maintains uniformity in information retrieval and presentation, regardless of the user’s chosen interface.</p> 
<p>Amazon Kendra also supports the use of <a href="https://docs.aws.amazon.com/kendra/latest/dg/s3-metadata.html" rel="noopener" target="_blank">metadata</a> for each source file, which enables both UIs to provide a link to its sources, whether it is the Spack documentation website or a CloudFront link. Furthermore, Amazon Kendra supports <a href="https://docs.aws.amazon.com/kendra/latest/dg/tuning.html" rel="noopener" target="_blank">relevance tuning</a>, enabling boosting certain data sources. For this solution, we boosted the results for the Spack documentation.</p>

It offers valuable data on usage patterns, conversation dynamics, user feedback, and query trends, allowing you to analyze and optimize your AI assistant’s performance and user interaction.</p>
